Production Integration

Build payment-gated survey flows with retry-safe APIs

COGNIT API is designed for web, mobile, and backend clients with strict idempotency, token-bound payment writes, and server-authoritative workflow transitions.

Envelope {"success":true,"data":...} or {"success":false,"error":...}
Idempotency Required on mutating routes to prevent duplicate writes on retries.
Auth Model Payment write token + turnstile validation (when enabled).

Core Concepts

Workflow Stages

consent -> user-details -> payment -> survey -> finished

Stage transitions are verified server-side. Client timers are UX-only.

Idempotency Keys

Send X-Idempotency-Key on all mutating endpoints.

Server stores request hash and returns replayed responses safely.

Payment Write Token

Issued by /payments/create and refreshed by payment status calls.

Required for upload URL and verify-upload endpoints.

Failure Model

Use stable error.code for product behavior, not raw message text.

Retry only when error.retryable=true.

Quickstart

  1. Create participant: POST /participants
  2. Record consent: POST /consent
  3. Create payment session: POST /payments/create
  4. Upload screenshot: POST /payments/{payment_public_id}/upload-url
  5. Verify screenshot: POST /payments/{payment_public_id}/verify-upload
  6. Fetch survey image: GET /images/random
  7. Submit response: POST /submit
curl -X POST "{{ base_url }}/payments/create" \
  -H "Content-Type: application/json" \
  -H "X-Idempotency-Key: 9ab87b4f-3f93-43f6-8f0e-5ac11d486f25" \
  -d '{
    "public_id":"<participant_public_id>",
    "amount":1,
    "turnstile_token":"<token_if_enabled>"
  }'

Integration Playbook

Frontend Client

  • Persist payment_id and idempotency key per create attempt.
  • Poll /payments/{id}/status on resume/reconnect.
  • Do not block user on QR fetch failures; use upi_link fallback.

Backend-to-Backend

  • Treat COGNIT as source of truth for payment verification state.
  • Replay mutating calls with same idempotency key on network failures.
  • Log X-Request-ID with every failed call for support triage.

Operational Guardrails

  • Surface actionable UI by mapping error.code to UX messages.
  • Alert on spikes in PAY_*, FRAUD_*, RATE_* categories.
  • Use contract files for CI validation to prevent drift.

Endpoint Catalog

GET /health

Service + database liveness check. Rate-limit exempt.

Constraints

  • No auth, no body.

Success Example

{"success":true,"data":{"status":"healthy","database":"connected"}}

Failure Modes

  • SYS_INTERNAL_ERROR: upstream/database unavailable.
POST /participants

Create participant profile and session identifiers.

Constraints

  • Required headers: Content-Type, X-Idempotency-Key
  • Required fields: username, email, phone, gender_code, age, location, language_code, prior_experience

Failure Modes

  • DUP_001_0001, DUP_001_0002, DUP_001_0003: identity conflicts
  • VAL_001_*: field-level validation
  • BOT_001_0001: turnstile failure (if enabled)
POST /payments/create

Create a payment session and issue payment write token.

Constraints

  • Headers: Content-Type, X-Idempotency-Key
  • Body: public_id, amount

Failure Modes

  • PAY_001_0003: invalid amount
  • NF_001_0001: participant missing
  • BOT_001_0001: turnstile failed
POST /payments/{payment_public_id}/verify-upload

Run OCR + anti-fraud verification and finalize payment state.

Constraints

  • Headers: Content-Type, X-Idempotency-Key, Authorization
  • Body: sha256, file_extension, plus upload_object_key or image_base64

Failure Modes

  • PAY_001_0008: max verify attempts exceeded
  • FRAUD_*: screenshot verification policy failures
  • DUP_003_*: duplicate/reused screenshot
POST /submit

Submit image description + feedback + survey telemetry metrics.

Constraints

  • Headers: Content-Type, X-Idempotency-Key
  • Required body: public_id, image_id, description, feedback, rating
  • Optional survey telemetry: survey_time_spent_ms, scroll depth, clicks, keypresses.

Failure Modes

  • VAL_002_*: content validation failures
  • DUP_002_*: duplicate survey/round submission
  • AUTH_001_0001, PAY_001_0007: access gating

Errors & Retries

Always branch logic by error.code, not by HTTP text.

Retryable

  • SYS_* transient backend failures
  • RATE_* after backoff
  • PAY_001_0001 with new payment session

User Action Required

  • VAL_* fix payload fields
  • DUP_* change user input/retry object
  • FRAUD_* upload a fresh compliant screenshot

Operational Logging

  • Capture X-Request-ID in client logs.
  • Include endpoint + idempotency key + code for support incidents.
  • Use /shared/contracts/error_contract.json for centralized mapping.
