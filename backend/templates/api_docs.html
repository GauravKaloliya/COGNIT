C.O.G.N.I.T. API Documentation

Overview

The C.O.G.N.I.T. (Cognitive Network for Image & Text Modeling) API powers a human-subjects image description study. The service coordinates consent, participant records, payments, image delivery, and submission storage with built-in quality, attention, and audit tracking.

Base URL

{{ base_url }}

Core Workflow

  1. Create a participant profile using /participants.
  2. Record consent using /consent before collecting data.
  3. Collect the entry fee with Razorpay using /payment/create-order and /payment/verify.
  4. Fetch images via /images/random (optionally exclude previously used images).
  5. Submit descriptions with ratings and feedback using /submit.

Request/Response Conventions

  • All JSON requests must include Content-Type: application/json.
  • Responses are JSON unless noted (images and logo are binary responses).
  • Timestamps are ISO 8601 strings in UTC.
  • Maximum request body size is 1 MB.

Security & Privacy Mechanisms

  • Rate Limiting: Default 200/day and 50/hour per IP, with tighter limits on sensitive routes.
  • Strict CORS: Only configured origins are allowed, no wildcard origins.
  • Security Headers: HSTS, CSP, Referrer-Policy, and clickjacking protections are enforced.
  • IP Hashing: IP addresses are irreversibly hashed with SHA-256 and a configurable salt before storage.
  • Input Validation: Server-side checks enforce email domains, phone formats, age bounds, rating ranges, and minimum word counts.
  • Audit & Performance Logs: Participant operations and response times are recorded in dedicated tables.

Rate Limit Summary

  • /participants: 30 requests per minute
  • /consent: 20 requests per minute
  • /submit: 60 requests per minute
  • /payment/create-order: 30 requests per minute
  • /payment/verify: 60 requests per minute
  • /docs: 30 requests per minute

API Endpoints

System & Documentation

GET /health ▶

Performs a health check across the database and image storage layer. This endpoint is exempt from rate limiting to support uptime monitoring.

Response

{
  "status": "healthy",
  "timestamp": "2024-01-01T00:00:00+00:00",
  "services": {
    "database": "connected",
    "images": "accessible"
  }
}

If a dependency is unavailable the status becomes degraded and the relevant service contains an error message.

Participants & Consent

POST /participants ▶

Creates a participant record. The API validates username format, email domain, Indian phone numbers, and an age range of 13-100.

Rate Limit: 30 per minute

Request Body

{
  "participant_id": "uuid-or-custom-id",
  "session_id": "session-token",
  "username": "letters_numbers_underscores",
  "email": "name@gmail.com",
  "phone": "+91XXXXXXXXXX",
  "gender": "female",
  "age": 24,
  "place": "Hyderabad",
  "native_language": "Telugu",
  "prior_experience": "No"
}

Response (201)

{
  "status": "success",
  "participant_id": "user-123",
  "participant_fk": 42,
  "message": "Participant created successfully"
}

Validation Errors (400)

{
  "error": "Validation failed",
  "details": {
    "age": "Age is required",
    "gender": "Gender is required"
  }
}

Duplicate Participant (409)

{
  "error": "Participant ID already exists"
}
GET /participants/<participant_id> ▶

Fetches participant metadata, including consent status. This endpoint is useful for resuming sessions or admin checks.

Path Parameters

Name Type Required Description
participant_id string Yes Participant identifier used during registration

Response

{
  "participant_id": "user-123",
  "username": "ava",
  "email": "ava@gmail.com",
  "phone": "+919876543210",
  "gender": "female",
  "age": 24,
  "place": "Hyderabad",
  "native_language": "Telugu",
  "prior_experience": "No",
  "consent_given": true,
  "created_at": "2024-01-01 00:00:00"
}

Not Found (404)

{
  "error": "Participant not found"
}
POST /consent ▶

Records consent for an existing participant and stamps the consent time. Consent must be true to proceed.

Rate Limit: 20 per minute

Request Body

{
  "participant_id": "user-123",

Response

{

  "message": "Consent recorded successfully",
  "timestamp": "2024-01-01T00:00:00+00:00"

Errors

Payments

POST /payment/create-order ▶

Creates (or reuses) a Razorpay order for the entry fee. If a recent unpaid order exists, the API returns the existing order ID.

Rate Limit: 30 per minute

Request Body

{
  "participant_id": "user-123"
}

Response

{
  "order_id": "order_N7k9p0n123",
  "key": "rzp_live_...",
  "amount": 100,
  "currency": "INR"
}

Errors

{
  "error": "Payment gateway not configured"
}
POST /payment/verify ▶

Validates Razorpay payment signatures after checkout and updates participant payment status to paid.

Rate Limit: 60 per minute

Request Body

{
  "razorpay_order_id": "order_N7k9p0n123",
  "razorpay_payment_id": "pay_N7k9p0n123",
  "razorpay_signature": "generated_signature"
}

Response

{
  "status": "verified"
}

Invalid Signature (400)

{
  "error": "Invalid signature"
}
POST /payment/webhook ▶

Processes Razorpay webhook events (typically payment.captured). Use the raw request body and include the X-Razorpay-Signature header.

Headers

X-Razorpay-Signature: <signature>

Response

{
  "status": "ok"
}

Errors

{
  "error": "Missing webhook signature"
}

Images & Assets

Returns a random image available for annotation. Use exclude to avoid already-seen image IDs.

Query Parameters

Name Type Required Description
exclude string No Comma-separated list of image IDs to skip

Response

  "image_url": "/images/aurora-lake.svg"
}

No Images Available (404)

{
  "error": "No images available"
}
GET /images/<image_id> ▶

Serves image binaries from the image store. SVG images are returned with the correct MIME type.

Path Parameters

Name Type Required Description
image_id string Yes The file name of the image

Response

Binary image data
GET /logo ▶

Fetches the C.O.G.N.I.T. logo. The API attempts to serve the image from GitHub and falls back to local storage.

Response

Binary image data (PNG)

Submissions

POST /submit ▶

Submits a participant response. The API enforces consent, paid status, and attention-quality checks before storing the submission.

Rate Limit: 60 per minute

Request Body

{
  "participant_id": "user-123",
  "session_id": "session-456",
  "image_id": "aurora-lake.svg",
  "image_url": "/images/aurora-lake.svg",
  "survey_index": 0,
  "description": "At least 60 words describing the image...",
  "rating": 8,
  "feedback": "Interesting scene with depth",
  "time_spent_seconds": 45,
  "is_survey": false
}

Behavior & Validation

  • Participant must exist, have consent recorded, and have payment_status = paid.
  • image_url, survey_index, is_survey, and time_spent_seconds are optional.
  • description must meet the minimum word count (default 60 words).
  • rating must be an integer between 1 and 10.
  • feedback must be at least 5 characters.
  • Attention check images are evaluated automatically and update attention stats.
  • Submissions record quality scores and attention flags for downstream analysis.

Response

{
  "status": "ok",
  "word_count": 78,
  "attention_passed": true,
  "quality_score": 0.84
}

Errors

{
  "error": "Payment required"
}

Code Examples

JavaScript / Fetch

// Create participant
const participantResponse = await fetch('/participants', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    participant_id: 'user-123',
    session_id: 'session-456',
    username: 'ava_1',
    email: 'ava@gmail.com',
    gender: 'female',
    age: 24,
    place: 'Hyderabad',
    native_language: 'Telugu',
    prior_experience: 'No'
  })
});

// Record consent
await fetch('/consent', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ participant_id: 'user-123', consent_given: true })
});

// Create payment order (Razorpay checkout follows client-side)
const orderResponse = await fetch('/payment/create-order', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ participant_id: 'user-123' })
});
const order = await orderResponse.json();

// Get a random image
const imageResponse = await fetch('/images/random');
const image = await imageResponse.json();

// Submit participant data
const submission = {
  participant_id: 'user-123',
  session_id: 'session-456',
  image_id: image.image_id,
  image_url: image.image_url,
  description: 'A detailed description that exceeds the minimum word count...',
  rating: 8,
  feedback: 'Clear contrast and composition.',
  time_spent_seconds: 48,
  is_survey: false
};

const submitResponse = await fetch('/submit', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(submission)
});
const result = await submitResponse.json();
console.log(result);

Python / Requests

import requests

base_url = "http://localhost:5000"

participant_payload = {
    "participant_id": "user-123",
    "session_id": "session-456",
    "username": "ava_1",
    "gender": "female",
    "age": 24,
    "place": "Hyderabad",
    "native_language": "Telugu",
    "prior_experience": "No"
}

requests.post(f"{base_url}/participants", json=participant_payload)

requests.post(
    f"{base_url}/consent",
    json={"participant_id": "user-123", "consent_given": True}
)

image = requests.get(f"{base_url}/images/random").json()

submission_payload = {
    "participant_id": "user-123",
    "session_id": "session-456",
    "image_id": image["image_id"],
    "image_url": image["image_url"],
    "description": "A detailed description that exceeds the minimum word count...",
    "rating": 7,
    "feedback": "Good lighting and composition.",
    "time_spent_seconds": 42
}

submission = requests.post(f"{base_url}/submit", json=submission_payload)
print(submission.json())

Error Handling

The API returns consistent JSON error responses. Clients should use HTTP status codes to drive retry logic and UX messaging.

HTTP Status Codes

Code Meaning Description
200 OK Successful read, update, or verification
201 Created Participant record created
400 Bad Request Validation failures or missing fields
403 Forbidden Consent or payment requirements unmet; flagged attention status
404 Not Found Resource is missing (participant or image)
409 Conflict Duplicate participant record
429 Too Many Requests Rate limit exceeded
500 Internal Server Error Unexpected database or configuration failure

Error Response Format

{
  "error": "Description of what went wrong",
  "details": "Optional additional information"
}

Common Validation Errors

  • Minimum 60 words required — Description is too short.
  • rating must be an integer between 1-10 — Rating is outside the accepted range.
  • comments must be at least 5 characters — Feedback is too short.
  • Participant ID already exists — The participant_id is not unique.
  • Participant not found. Please complete registration first. — Participant ID missing from the database.
  • Payment required — Payment status is not marked as paid.
  • Consent required. Please complete the consent process. — Consent not recorded.
  • Payment gateway not configured — Razorpay credentials missing in the environment.
  • Invalid signature — Razorpay signature verification failed.
  • Account flagged for low attention quality — Participant failed attention checks.

Rate Limit Error (429)

{
  "message": "Rate limit exceeded"
}
